# Domain docs

## Layout and reading rules

This is a single-context repository.

Before exploring the codebase, read root `GLOSSARY.md` when present and
the ADRs in `docs/adr/` relevant to the work.

If these files do not exist, proceed silently. Create domain documentation
lazily through domain-modeling when terminology or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, tests, and implementation.
Reconsider invented synonyms; note genuine terminology gaps for
domain-modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR and
explain why reopening that decision is warranted.
